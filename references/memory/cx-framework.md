# Contributor Experience (CX) Framework

<!-- last-verified: 2026-08-29 -->

Operational rules and models to ensure an effortless path from discovery to first merged Pull Request.

---

## 🗺️ 1. The Contributor Journey (11 Stages)

```text
1. Discover       → Search, social, README first screen
2. Understand     → 15-second value proposition + clear archetype
3. Install        → 1-line copy-pasteable command
4. Run & Test     → Working local dev environment in < 10 minutes
5. Find an Issue  → Curated "Good First Issue" with isolated scope
6. Understand Task→ Clear inputs, outputs, prerequisites, and file pointers
7. Code           → Pre-configured linters, typecheckers, tests
8. Test Locally   → Deterministic test suite passing locally
9. Open PR        → Pre-filled PR template with self-review checklist
10. Review        → Empathetic, fast (<48h) maintainer feedback
11. Recognition   → Automatic credit in CONTRIBUTORS.md & release notes
```

---

## 🪜 2. The 6-Tier Contributor Ladder

```text
[6] Core Maintainer     → Strategic direction, security keys, final releases
[5] Maintainer          → Triage, PR review & merge authority, milestone planning
[4] Regular Contributor → Subsystem ownership, code review assistance, RFC authoring
[3] Contributor         → Multiple merged PRs across features/docs
[2] First-Time Contributor → First PR submitted or merged
[1] Observer / User     → Stars, watches, issue reporters, discussion participants
```

---

## ⏱️ 3. Onboarding Friction Index

```text
Friction Level    Expected Setup Time    Key Causes
──────────────────────────────────────────────────────────────────────
Minimal (<15m)    1 – 15 mins            Single command setup, mock data ready
Moderate (15-45m) 15 – 45 mins           Env vars required, local database needed
High (>45m)       45 – 120 mins          Complex native toolchains, manual keys
Blocker (Fail)    > 120 mins             Broken docs, hidden prerequisites, failing CI
```
